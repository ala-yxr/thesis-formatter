# 论文格式助手

把一篇毕业论文的 Word 文档自动修改为学校要求的格式：内置多套**学校格式预设**（默认重庆工程学院《附件8》标准：页边距 2.5cm、行距固定 20 磅、宋体小四 + Times New Roman、一级三号黑体居中 / 二级小三号黑体居左 / 三级四号黑体居左右缩两字、**一级标题「1 绪论」体例（第1章 → 1，附录与图A1）**、图题表题五号宋体、参考文献五号宋体序号左顶格、**三线表（清表级与行级边框，顶底线 1.5 磅 + 栏目线 0.75 磅）**、目录小四宋体 2-4 级右缩两字并**自动更新页码**、**页眉自动显示一级标题（章名）**、**正文引用标注 `[1]` 自动改为右上角上标**、**图表改用 Word 真题注（题注样式 + SEQ 域，图4.1 / 表3.1）**、**每章末尾补分节符（下一页）**、**清除突出显示底色**、**删除中西文之间的空格**、一级标题换页、前置罗马数字 / 主体阿拉伯数字分节页码等）。全部在浏览器本地完成，**文件不会上传到任何服务器**。

页面左上角标题旁的 `v1.6.5` 就是当前工具版本，导出的文档名也会带同样的后缀（`CYX_毕业设计.docx` → `CYX_毕业设计_v1.6.5.docx`），便于分辨手上这份是哪一版跑出来的；对已经带版本号的文件再跑一遍时，旧后缀会先被替换掉，不会越拼越长（`CYX_毕业设计_v1.6.2.docx` → `CYX_毕业设计_v1.6.5.docx`）。

## 使用方法

1. 双击打开 `index.html`（推荐 Chrome / Edge 浏览器）
2. 将 `.docx` 论文拖入页面（或点击选择文件）
3. 左侧顶部「学校要求」下拉框选择学校，自动套用该校全部格式要求（仍可手动微调各项）
4. 点击「一键格式化」→ 预览效果 → 「下载 Word 文档」

### 添加学校要求（上传要求文档）

下拉框旁的「＋ 添加学校要求」可上传该校的要求文档（.docx）：
先在设置面板中调整好该校的格式要求，上传要求文档并命名学校，即保存为该校预设（存入浏览器本地），下次直接切换；选中自定义学校后可点「删除该校」移除。

### 新增内置学校预设

编辑 `js/presets.js`，在 `SCHOOL_PRESETS` 数组中追加一条即可：

```js
{
  id: 'my-school',               // 唯一标识
  name: '某大学（要求附件X）',     // 下拉框显示名
  desc: '格式要点简介',           // 切换后显示的说明
  settings: { /* 各格式字段，见同文件示例 */ }
}
```

## 技术原理

- 直接解析并改写 `.docx` 内部的 OOXML（`word/document.xml`），而非重新生成文档
- 因此**图片、公式（OMML）、表格、页眉页脚全部原样保留**，仅重排字体/字号/行距/缩进/对齐/页边距/页码
- 规则化自动识别论文结构：封面（不动）→ 题目 → 摘要 → 关键词 → Abstract → Keywords → 目录 → 章节标题（`第X章` / `1 绪论` / `1.1` / `1.1.1` / 附录内 `A.1`）→ 正文 → 图表题注 → 参考文献 → 致谢 / 附录（附录内 A.1 一级小节按二级标题排版）
- 引用标注上标：把正文中 `[1]`、`[3,5]`、`[7-9]` 形式的引用标注拆分为独立 run 并加 `<w:vertAlign w:val="superscript"/>`；**参考文献表自身的条目序号保持原样不加上标**，封面页不动
- 真题注：图片题注改成「题注」样式 + `SEQ 图 \* ARABIC` 域、表格题注同理用 `SEQ 表`，两者各自计数、互不干扰；每章第一条题注带 `\r 1` 实现按章重新编号（「图4.1」= 第4章第1图），附录里的图用字母编号（「图A1」，字母与序号之间不带「.」）。章节标题带「标题 N」样式，Word 打开时刷新 TOC 域才能收全条目、页眉的 `STYLEREF` 才能取到章名——源文档没有标题样式时由工具现建（只声明 `outlineLvl`，字号字体仍走段落直接格式，不改版面）
- 交叉引用同步：题注改号后，正文里「如图4-1所示」「表4-2~表4-4」一并改为「图4.1」「表4.2~表4.4」，否则图题和引用对不上
- 分节符：每章末尾补 `<w:sectPr><w:type w:val="nextPage"/>`。往回跨空段找已有分节符（Word 常把目录和正文包在 `<w:sdt>` 里，只在紧邻段落上看会漏判），已有 nextPage 则跳过、连续分节符就地升级成 nextPage。`nextPage` 本身带换页效果，**不再叠加分页符**，否则章间会多出空白页
- 中西文空格：删除中文与英文/数字之间的空格，但标题、目录、题注里「编号 + 文字」的那个空格按附件8 保留（`1 绪论`、`图4.1 系统图`）；正文与表格单元格同一口径
- 页眉页脚里的孤儿标点：来源文档常在页码域前留一个只含顿号的 run（排出来是页脚上的「、33」），收得极紧——整 run 只有一个全角标点、与 `PAGE` 域同段、且在文本框之外才删
- 依赖：`libs/jszip.min.js`（解压/压缩）、`libs/mammoth.browser.min.js`（预览渲染），均已本地化，可离线使用

```

```

## 开发测试

```bash
npm test              # Node 引擎测试 + 浏览器端到端测试（需在上级目录放一份真实论文 .docx）
npm run test:node     # 只跑 Node 引擎测试（快，用 xmldom）
npm run test:browser  # 只跑浏览器端到端（真实 Edge/Chrome 的 DOMParser/XMLSerializer）
node test/serve.mjs   # 启动本地服务器后，用无头浏览器跑 test/smoke.html
```

**为什么要有浏览器端到端测试**：Node 端用的 `@xmldom/xmldom` 与浏览器的 XML 实现行为不一致，而导出的 docx 是浏览器产出的。同一个写法在两边可能一个正常一个产出损坏文件 —— v1.6.1 修的「文件已损坏」就是这么漏过去的。**改完 `formatter.js` 一定要跑 `npm test`（默认会带上浏览器那一遍）**，只看 Node 那半场的绿灯不作数。

## 性能说明（v1.1）

- 格式化本身在 1~2 秒内完成，完成后**下载按钮立即可用**，无需等待预览
- 预览在后台异步生成（页面有黄色状态条提示），仅内嵌前 12 张图（自动压缩到 1000px 内），其余图片以占位图显示 —— 下载的 Word 中图片完整保留
- 预览 HTML 体积从全量内嵌的 ~7.4MB 降至 ~2.3MB

## 更新记录

- **v1.6.5**：**修复「段落之间带换行的文档整篇处理不了」**（严重）。按缩进排过版的工具（本项目的 md2docx 就是 —— 它用多行模板拼 XML 图好读）生成的 `document.xml` 在标签之间留着换行与缩进；解析后这些换行是**空白文本节点**，而 `replaceTocWithField` 删除旧目录区时拿 `nextSibling` 直接当元素用，摸到文本节点一调 `getElementsByTagNameNS` 就抛 `TypeError`，整篇处理中断（浏览器里表现为丢进去报「处理失败」或毫无反应）。修法是在 `allByNs()` 这个收口处加节点类型防御，全部调用点一并免疫 —— **没有用 `nodeType === 1` 判断**，因为 `Document` 也要走这条路（`ensureTocStyles` 传的就是文档对象）。**另补一条回归测试**：把夹具的 `document.xml` 每个标签之间插上换行再跑一遍，必须与原夹具同样通过。夹具是 Word 存出来的紧凑一行（全篇只有 1 个换行），原先永远覆盖不到这个形态 —— 2026-09-15 真实产物就是这么栽的：单测与端到端全绿，用户把文档丢进去却用不了，查了半天才发现夹具与真实产物的差别只在换行。
- **v1.6.4**：**修复「输出文档正文内容全部消失」**（严重）。**把已经格式化过一次的文档再格式化一遍**（输出文件名带版本号之后，直接拿上一次的产出接着跑是很自然的用法）时，旧目录只被删掉前半截：正文里残留半截旧目录条目，还留下一个**没有 `begin` 与之配对的 `end` 域字符**。Word 打开这种文档会提示更新域，更新时把其后的内容一并当成域的一部分处理 —— 正文整片不见。修了三处：① 目录条目判定补上 `PAGEREF _TocN`／`HYPERLINK _TocN` 特征（本工具生成的目录条目正文里不带页码，域结果是空的，原先的点线/页码结尾/目录样式/超链接四条特征全都认不出来，于是目录区边界落在目录中间）；② 含域字符的段落不再被当成「空段」保留（旧目录域末尾那个只有 `end` 的段落原先会被当空段留一个下来）；③ 删除旧目录区时若正处在未闭合的域内部，不再被分节段打断。**另加导出前兜底**：`repairFields()` 统一检查全文域字符，删掉多余的 `end`/`separate`、给没闭合的 `begin` 补 `end`，因此**手上已经坏掉的文档再跑一遍这个工具也能修好**。顺带修掉 `childByNs(null)` 的崩溃（段落没有 `pPr` 时抛异常）。格式化现在**幂等**：同一份文件跑第 2、3 遍，段落数与字数与第 1 遍完全一致。

## 已知限制

- **改代码后请务必跑 `npm test`（含浏览器端到端一遍）**：Node 单测环境（xmldom）与浏览器行为不同，只跑 Node 那半场可能漏掉「导出的文档 Word 打不开」这类问题。详见「开发测试」一节
- 目录：自动识别（「目录/目次」标题、Word 目录样式 TOC、超链接条目、标题+tab+页码、点线页码等特征），条目按小四宋体 2-4 级重排（下级右缩两字）；**默认替换为 Word 目录域并在文档中写入「打开时自动更新域」标记 —— 打开文档时 Word 会提示是否更新域（选「是」）即可自动刷新页码**；若关闭「自动更新目录页码」开关，则仍需右键目录 →「更新域」
- 公式：不改动；预览中公式可能显示不完整，以 Word 为准
- 表格：默认改为三线表 —— **同时清除表级 `w:tblBorders` 与行级 `w:tblPrEx` 边框**（部分模板在每行上带全网格边框，会覆盖表级设置），仅保留顶线/底线 1.5 磅 + 栏目线 0.75 磅，可在设置中关闭；表内文字不重排
- 图片：所有含图片的段落自动改为单倍行距（避免固定行距截断图片），图片本身原样保留
- 引用标注上标：只处理「正文」类段落，参考文献表条目、封面、图题、公式段落不受影响；已带域、制表符或换行符的 run 会跳过（避免破坏这些元素）；`[J]`/`[M]`/`[C]` 等文献类型标识不会被误判（只匹配纯数字及 `,`/`-` 组合）
- 图表题注：**按「章」编号，图、表各自一个计数器**；没有题注的图表会自动补一条占位题注（内容为「图4.1」「表3.1」，需自行补图名）；已有题注在同一段或紧邻的下一段时直接原地改写，不动图表位置；编号按一级标题（含「第X章」与「X 绪论」两种写法）重置，因此**章标题必须是可识别的一级标题**，否则编号会一直累加
- 交叉引用同步：只把「图4-1」「表4-2」这类编号中的连接符由 `-` 改成 `.`（等长替换，不动其它文字）；「图表」连写时不会误判；题注段落本身与目录条目不改
- 目录（反复格式化）：工具对「已经格式化过一次的文档」可以直接再跑，结果与第一遍一致（幂等）。输入文档的目录域本来就是坏的（半截目录留在正文里、域字符不配平）时，重新跑一遍会删掉残留的旧目录条目并修好域字符，但**目录条目数量可能不全**（改由 Word 打开时更新域重新生成即可）
