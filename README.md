# 论文格式助手

把一篇毕业论文的 Word 文档自动修改为学校要求的格式：内置多套**学校格式预设**（默认重庆工程学院《附件8》标准：页边距 2.5cm、行距固定 20 磅、宋体小四 + Times New Roman、一级三号黑体居中 / 二级小三号黑体居左 / 三级四号黑体居左右缩两字、**标题编号体例（一级「第1章 绪论」→「1 绪论」、三级「3.1.1系统目标」→「3.1.1 系统目标」，附录与图A1 另行编号）**、图题表题五号宋体、参考文献五号宋体序号左顶格、**三线表（清表级与行级边框，顶底线 1.5 磅 + 栏目线 0.75 磅）**、**表格内文字统一五号宋体 + Times New Roman（表头不加粗）**、目录小四宋体 2-4 级右缩两字并**自动更新页码**、**页眉自动显示一级标题（章名）**、**正文引用标注 `[1]` 自动改为右上角上标**、**图表改用 Word 真题注（题注样式 + SEQ 域，图4.1 / 表3.1）**、**每章末尾补分节符（下一页）**、**清除底色（突出显示 + 表格/段落底纹）**、**删除中西文之间的空格**、一级标题换页、前置罗马数字 / 主体阿拉伯数字分节页码等），**并可选地把一份模板文档的封面与原创性声明页整段照搬到本篇最前面**（`前置页（封面 / 声明页）` → 选择模板文档 → 勾选启用）。全部在浏览器本地完成，**文件不会上传到任何服务器**。

页面左上角标题旁的 `v1.7.0` 就是当前工具版本，导出的文档名也会带同样的后缀（`CYX_毕业设计.docx` → `CYX_毕业设计_v1.7.0.docx`），便于分辨手上这份是哪一版跑出来的；对已经带版本号的文件再跑一遍时，旧后缀会先被替换掉，不会越拼越长（`CYX_毕业设计_v1.6.2.docx` → `CYX_毕业设计_v1.7.0.docx`）。

## 使用方法

1. 双击打开 `index.html`（推荐 Chrome / Edge 浏览器）
2. 将 `.docx` 论文拖入页面（或点击选择文件）
3. 左侧顶部「学校要求」下拉框选择学校，自动套用该校全部格式要求（仍可手动微调各项）
4. 点击「一键格式化」→ 预览效果 → 「下载 Word 文档」

### 添加学校要求（上传要求文档）

下拉框旁的「＋ 添加学校要求」可上传该校的要求文档（.docx）：
先在设置面板中调整好该校的格式要求，上传要求文档并命名学校，即保存为该校预设（存入浏览器本地），下次直接切换；选中自定义学校后可点「删除该校」移除。

### 新增内置学校预设

编辑 `js/presets.js`，在 `SCHOOL_PRESETS` 数组中追加一条即可：

```js
{
  id: 'my-school',               // 唯一标识
  name: '某大学（要求附件X）',     // 下拉框显示名
  desc: '格式要点简介',           // 切换后显示的说明
  settings: { /* 各格式字段，见同文件示例 */ }
}
```

## 技术原理

- 直接解析并改写 `.docx` 内部的 OOXML（`word/document.xml`），而非重新生成文档
- 因此**图片、公式（OMML）、表格、页眉页脚全部原样保留**，仅重排字体/字号/行距/缩进/对齐/页边距/页码
- 规则化自动识别论文结构：封面（不动）→ 题目 → 摘要 → 关键词 → Abstract → Keywords → 目录 → 章节标题（`第X章` / `1 绪论` / `1.1` / `1.1.1` / 附录内 `A.1`）→ 正文 → 图表题注 → 参考文献 → 致谢 / 附录（附录内 A.1 一级小节按二级标题排版）
- 引用标注上标：把正文中 `[1]`、`[3,5]`、`[7-9]` 形式的引用标注拆分为独立 run 并加 `<w:vertAlign w:val="superscript"/>`；**参考文献表自身的条目序号保持原样不加上标**，封面页不动
- 真题注：图片题注改成「题注」样式 + `SEQ 图 \* ARABIC` 域、表格题注同理用 `SEQ 表`，两者各自计数、互不干扰；每章第一条题注带 `\r 1` 实现按章重新编号（「图4.1」= 第4章第1图），附录里的图用字母编号（「图A1」，字母与序号之间不带「.」）。章节标题带「标题 N」样式，Word 打开时刷新 TOC 域才能收全条目、页眉的 `STYLEREF` 才能取到章名——源文档没有标题样式时由工具现建（只声明 `outlineLvl`，字号字体仍走段落直接格式，不改版面）
- 交叉引用同步：题注改号后，正文里「如图4-1所示」「表4-2~表4-4」一并改为「图4.1」「表4.2~表4.4」，否则图题和引用对不上
- 分节符：每章末尾补 `<w:sectPr><w:type w:val="nextPage"/>`。往回跨空段找已有分节符（Word 常把目录和正文包在 `<w:sdt>` 里，只在紧邻段落上看会漏判），已有 nextPage 则跳过、连续分节符就地升级成 nextPage。`nextPage` 本身带换页效果，**不再叠加分页符**，否则章间会多出空白页
- 中西文空格：删除中文与英文/数字之间的空格，但标题、目录、题注里「编号 + 文字」的那个空格按附件8 保留（`1 绪论`、`图4.1 系统图`）；正文与表格单元格同一口径
- 页眉页脚里的孤儿标点：来源文档常在页码域前留一个只含顿号的 run（排出来是页脚上的「、33」），收得极紧——整 run 只有一个全角标点、与 `PAGE` 域同段、且在文本框之外才删
- 依赖：`libs/jszip.min.js`（解压/压缩）、`libs/mammoth.browser.min.js`（预览渲染），均已本地化，可离线使用

## 目录结构

```
论文格式助手/
├── index.html          # 主页面
├── css/style.css       # 样式
├── js/formatter.js     # 核心格式化引擎（结构识别 + OOXML 编辑）

└── test/
    ├── run-test.mjs      # Node 引擎测试（npm run test:node）

    ├── serve.mjs         # 本地静态服务器（手工冒烟测试用）
    └── smoke.html        # 浏览器手工冒烟测试页
```

## 开发测试

```bash
npm test              # Node 引擎测试 + 浏览器端到端测试（需在上级目录放一份真实论文 .docx）
npm run test:node     # 只跑 Node 引擎测试（快，用 xmldom）
npm run test:browser  # 只跑浏览器端到端（真实 Edge/Chrome 的 DOMParser/XMLSerializer）
node test/serve.mjs   # 启动本地服务器后，用无头浏览器跑 test/smoke.html
```

**为什么要有浏览器端到端测试**：Node 端用的 `@xmldom/xmldom` 与浏览器的 XML 实现行为不一致，而导出的 docx 是浏览器产出的。同一个写法在两边可能一个正常一个产出损坏文件 —— v1.6.1 修的「文件已损坏」就是这么漏过去的。**改完 `formatter.js` 一定要跑 `npm test`（默认会带上浏览器那一遍）**，只看 Node 那半场的绿灯不作数。

## 性能说明（v1.1）

- 格式化本身在 1~2 秒内完成，完成后**下载按钮立即可用**，无需等待预览
- 预览在后台异步生成（页面有黄色状态条提示），仅内嵌前 12 张图（自动压缩到 1000px 内），其余图片以占位图显示 —— 下载的 Word 中图片完整保留
- 预览 HTML 体积从全量内嵌的 ~7.4MB 降至 ~2.3MB

## 更新记录

- **v1.7.0**：**新增「套用模板前置页」**。设置面板多了一组「前置页（封面 / 声明页）」：选一份模板文档，工具取它「摘要」标题之前的部分（封面 + 原创性声明页，含图片与封面信息表），整段照搬到本篇最前面，并替换掉本篇自己的封面区；摘要及以后仍用本篇的内容，随后照常套用全部格式规则。**以本篇为底板、只把模板前置页插到最前**，而不是拿模板当底板 —— 要搬的资源少得多（模板侧通常只有一张校徽，本篇侧有十几二十张插图）。前置页读的是模板 `document.xml` 里「摘要」标题之前的所有顶层元素，连同它引用的图片一起搬：图片落成 `word/media/front1.png` 这类独立前缀（绝不撞本篇已有的 `imageN`），并补关系、补 `[Content_Types].xml` 里的图片格式声明、补模板根上有而本篇根上没有的 `xmlns:` 声明（缺了就是「未绑定的前缀」，Word 直接判文档损坏 —— `换正文.mjs` 踩过）。**模板前置页末尾那段自带 `sectPr`**，落进前置边界后会自动被归入「前置部分」，因此版面与页码都按原样保留：页边距、纸张照抄模板，封面与声明页不编页码，罗马数字页码仍从摘要页的 Ⅰ 开始。**模板前置页的页眉页脚一律不搬**：封面与声明页不该有页码、也不该印页眉（附件8 的范本本身也是空的），而且搬过来的部件会不会被 `addFooter` 挑中当页码页脚，取决于 `[Content_Types].xml` 里的先后顺序，那是碰运气；模板里真有内容的页眉页脚会被**点名告知**而不是静默丢掉（结果面板会写明「模板前置页的页眉未搬运」）。模板解析一次就记在浏览器里（含图片 base64），下次打开不用重选，也不分学科共用。**另加回归测试** `test/front-matter.mjs`：合成一份带校徽、空页眉、有字页眉、封面表格与 `sectPr` 的模板，断言前置页逐元素顺序与模板一致、图片落盘且 rId 不悬空、前置节页边距与不编页码保持、本篇旧封面被替换、摘要节页码为罗马数字从 1 开始。修掉开发中发现的插入顺序反转（循环里每轮都插到 `body.firstChild`，24 个元素整体倒序，校徽跑到声明页后面）——现已改为先取定锚点再按原序插入。

- **v1.6.7**：**修复「表格内的文字格式一个字都没被改到」+ 清除表格与说明框的底纹**。根因：收集正文段落的 `collectParas` 只遍历 `body` 的直接子元素（`body.childNodes` 里 `localName === 'p'` 的那些），而**表格里的段落嵌套在 `w:tbl` 下面**，整批不在处理列表里 —— `applyFormatting` 那套字体、字号、缩进、对齐对表内文字完全够不着，表里混着宋体/黑体/Consolas、字号 20（10pt）与 32（16pt）并存，作者看到的正是「正文都改好了、表格里原样不动」。修法是新增一道独立工序 `formatTableText()`：对每张表（前置部分的封面/声明页表格跳过）逐单元格逐段按附件8 的「**表序、表名和表格内字体均为五号宋体**」落地 —— 中文宋体、西文与数字 Times New Roman、`sz` 21（五号 = 10.5pt）；标准里没给表头开例外（样章三处重复「五号宋体」），所以**表头也五号、不加粗**，原文档表头那点黑体加粗一并去掉。表内段落**只改 run 级格式，不动段落自己的对齐与缩进**（保持原有版式）。**底纹一并清除**：`clearHighlight` 原先只删 `w:highlight`（工具条上的「突出显示」），注释里还明确写着「字符底纹 `w:shd` 不动 —— 它常被模板用来做表头底色等正常排版」；但附件8 的表格是纯三线表（顶线 1.5 磅、栏目线 0.75 磅、底线 1.5 磅），通篇不该有底色，源文档里那种浅蓝表头（`DCE6F1`）与正文说明框的浅灰蓝（`F2F4F7`）都要去掉。新增 `clearShading()`，把五个层级的底纹（`rPr` 字符 / `pPr` 段落 / `tcPr` 单元格 / `trPr`·`tblPrEx` 行 / `tblPr` 整表）一次清干净，与三线表、换页等工序同一口径 —— **前置部分（封面/学生声明）的底纹一律不动**（封面表格是学校模板的一部分，改了就不像模板了）。单元格底纹特意**不**放进 `formatTableText` 里做，否则「清除底色」开关关掉时表底纹只清一半，变成两套口径。设置面板加「表格内文字统一五号宋体（表头不加粗）」开关与新的一组「表格」选项（中文字体、字号），「清除突出显示」相应改名为「清除底色（突出显示 + 表格/段落底纹）」。**另加回归测试**：构造封面表格（黑体三号加粗 + `D9E2F3`）、正文表格（黑体加粗表头 + Consolas 数据 + `DCE6F1`）、段落说明框（`F2F4F7`）三者并存的文档，断言正文表格 run 全部合规、表内底纹清空、说明框底纹清空、**封面表格原样保留**；红绿验证过 —— 把 `tableText` 短路、`clearShading` 返回 0 时测试确实变红，红时的输出正是作者报的 `字段名[黑体/Consolas/20/粗]`。真实论文实测：582 个表内 run 全部「宋体 / Times New Roman / sz21 / 常规」，底纹残留 0 处，1 张封面表格未动，清掉单元格底纹 61 处 + 段落底纹 3 处、突出显示 207 处，文件 2735626 → 2150223 字节。
- **v1.6.6**：**修复「三级标题编号后没写空格就掉成正文」**。识别三级标题的 `RE.h3` 要求编号后必须有一个空白字符（`\s`），而同文件里二级标题用的是 `\s*`（可有可无）—— 两条体例不一致。于是把三级标题写成「3.1.1系统目标」（附件8 要求的是「数字与文字间隔一字符」，但作者未必每处都写了空格）时：`RE.h3` 不命中，`RE.h2` 又因 `(?![\d.])` 前瞻撞上第二个小数点也不命中，整段落到 `body` —— **宋体小四、两端对齐、首行缩进 480，标题的字体、字号、对齐、缩进四处全丢**，而写成「1.1.1 研究背景」的照常正确，表现为「同一篇论文里第一章的三级标题对、第三章的不对」。2026-09-16 曾鹏的论文第 3 章 9 个三级标题正是这样被排成正文的（全文实测 37 个三级标题，改前 9 个错、改后 0 个错）。修法两步：① `RE.h3` 的 `\s` 放宽成 `\s*`，与 `RE.h2` 对齐；② `rewriteChapterHeadings` 新增三级标题分支，把「3.1.1系统目标」补成「3.1.1 系统目标」（**只补空格，编号一个字符不改**；本来就有空格的跳过，不会补成两个）。补的空格不会被后面那道「删除中西文空格」的工序抹掉（`KEEP_NUM_ROLE` 含 `h3`，`NUM_HEAD` 会保护段首编号后的那个空格）。**另补回归测试**：构造含「1.1.1 有空格」「1.1.2无空格」「1.2.3节」（正文里的指代）「超长小数句」的文档，断言缺空格的被补上并按三级标题排版（黑体 sz28）、本来有空格的不补成两个、正文里的指代和长句一个字不动 —— 已做过红绿验证（把 `RE.h3` 改回 `\s` 时这条测试确实变红）。
- **v1.6.5**：**修复「段落之间带换行的文档整篇处理不了」**（严重）。按缩进排过版的工具（本项目的 md2docx 就是 —— 它用多行模板拼 XML 图好读）生成的 `document.xml` 在标签之间留着换行与缩进；解析后这些换行是**空白文本节点**，而 `replaceTocWithField` 删除旧目录区时拿 `nextSibling` 直接当元素用，摸到文本节点一调 `getElementsByTagNameNS` 就抛 `TypeError`，整篇处理中断（浏览器里表现为丢进去报「处理失败」或毫无反应）。修法是在 `allByNs()` 这个收口处加节点类型防御，全部调用点一并免疫 —— **没有用 `nodeType === 1` 判断**，因为 `Document` 也要走这条路（`ensureTocStyles` 传的就是文档对象）。**另补一条回归测试**：把夹具的 `document.xml` 每个标签之间插上换行再跑一遍，必须与原夹具同样通过。夹具是 Word 存出来的紧凑一行（全篇只有 1 个换行），原先永远覆盖不到这个形态 —— 2026-09-15 真实产物就是这么栽的：单测与端到端全绿，用户把文档丢进去却用不了，查了半天才发现夹具与真实产物的差别只在换行。
- **v1.6.4**：**修复「输出文档正文内容全部消失」**（严重）。**把已经格式化过一次的文档再格式化一遍**（输出文件名带版本号之后，直接拿上一次的产出接着跑是很自然的用法）时，旧目录只被删掉前半截：正文里残留半截旧目录条目，还留下一个**没有 `begin` 与之配对的 `end` 域字符**。Word 打开这种文档会提示更新域，更新时把其后的内容一并当成域的一部分处理 —— 正文整片不见。修了三处：① 目录条目判定补上 `PAGEREF _TocN`／`HYPERLINK _TocN` 特征（本工具生成的目录条目正文里不带页码，域结果是空的，原先的点线/页码结尾/目录样式/超链接四条特征全都认不出来，于是目录区边界落在目录中间）；② 含域字符的段落不再被当成「空段」保留（旧目录域末尾那个只有 `end` 的段落原先会被当空段留一个下来）；③ 删除旧目录区时若正处在未闭合的域内部，不再被分节段打断。**另加导出前兜底**：`repairFields()` 统一检查全文域字符，删掉多余的 `end`/`separate`、给没闭合的 `begin` 补 `end`，因此**手上已经坏掉的文档再跑一遍这个工具也能修好**。顺带修掉 `childByNs(null)` 的崩溃（段落没有 `pPr` 时抛异常）。格式化现在**幂等**：同一份文件跑第 2、3 遍，段落数与字数与第 1 遍完全一致。

## 已知限制

- **改代码后请务必跑 `npm test`（含浏览器端到端一遍）**：Node 单测环境（xmldom）与浏览器行为不同，只跑 Node 那半场可能漏掉「导出的文档 Word 打不开」这类问题。详见「开发测试」一节
- 目录：自动识别（「目录/目次」标题、Word 目录样式 TOC、超链接条目、标题+tab+页码、点线页码等特征），条目按小四宋体 2-4 级重排（下级右缩两字）；**默认替换为 Word 目录域并在文档中写入「打开时自动更新域」标记 —— 打开文档时 Word 会提示是否更新域（选「是」）即可自动刷新页码**；若关闭「自动更新目录页码」开关，则仍需右键目录 →「更新域」
- 公式：不改动；预览中公式可能显示不完整，以 Word 为准
- 表格：默认改为三线表 —— **同时清除表级 `w:tblBorders` 与行级 `w:tblPrEx` 边框**（部分模板在每行上带全网格边框，会覆盖表级设置），仅保留顶线/底线 1.5 磅 + 栏目线 0.75 磅，可在设置中关闭；**表内文字统一为五号宋体 + Times New Roman、表头不加粗**（附件8：「表序、表名和表格内字体均为五号宋体」，表头不开例外），**只改字体与字号，段落自身的对齐、缩进保持原样**；封面/学生声明页的表格不动
- 图片：所有含图片的段落自动改为单倍行距（避免固定行距截断图片），图片本身原样保留
- 引用标注上标：只处理「正文」类段落，参考文献表条目、封面、图题、公式段落不受影响；已带域、制表符或换行符的 run 会跳过（避免破坏这些元素）；`[J]`/`[M]`/`[C]` 等文献类型标识不会被误判（只匹配纯数字及 `,`/`-` 组合）
- 图表题注：**按「章」编号，图、表各自一个计数器**；没有题注的图表会自动补一条占位题注（内容为「图4.1」「表3.1」，需自行补图名）；已有题注在同一段或紧邻的下一段时直接原地改写，不动图表位置；编号按一级标题（含「第X章」与「X 绪论」两种写法）重置，因此**章标题必须是可识别的一级标题**，否则编号会一直累加
- 交叉引用同步：只把「图4-1」「表4-2」这类编号中的连接符由 `-` 改成 `.`（等长替换，不动其它文字）；「图表」连写时不会误判；题注段落本身与目录条目不改
- 套用模板前置页：模板必须能找到**「摘要」标题**（单独一段，中文或 Abstract 均可）作为界桩，找不到会报错拒收；模板前置页的**页眉页脚一律不搬**（封面与声明页不编页码、不印页眉），模板里真有内容的页眉页脚会在结果面板点名说明；模板里的**外链图片**（`http://…`）不搬；前置页只搬文字、表格、图片，域代码与批注等随段落一并照搬但不会重新编号；模板整篇记在浏览器 localStorage 里（含图片 base64），校徽这类大图可能让某些浏览器存不下 —— 此时会提示「本次仍可用、下次需重选」，不影响当次导出
- 目录（反复格式化）：工具对「已经格式化过一次的文档」可以直接再跑，结果与第一遍一致（幂等）。输入文档的目录域本来就是坏的（半截目录留在正文里、域字符不配平）时，重新跑一遍会删掉残留的旧目录条目并修好域字符，但**目录条目数量可能不全**（改由 Word 打开时更新域重新生成即可）
- 章标题体例：「第N章 标题」→「N 标题」只改**标题段与目录条目**（依据一级标题识别结果），正文里指代章节的「第5章」不动；中文数字章号按「一～九十九」转换，认不出来时（如「第壹章」）整个标题跳过不改；附录序号由附录个数决定（1 个不编、多个依序编 A/B/C），各附录原本就带字母时保留原字母；若附录标题在文档里排在「参考文献」之前而没有被判成附录，则不会被改写（正文部分也照旧按一级标题排版）
- 分节符：只加 `下一页` 分节符，**不额外加独立分页符**（`nextPage` 分节符本身就会换页，两者叠加会多出空白页）；源文档已有的分节符一律保留（连续分节符会就地升级为下一页）；每章页眉通过分节继承，若前置部分（封面/摘要/目录）的页眉需要单独设置，请先在 Word 中确认分节边界
- 清除底色：清除高亮（`w:highlight`）与**全部层级的底纹**（`w:shd` —— 字符 / 段落 / 表格单元格 / 行 / 整表），**保留下划线、加粗、斜体、删除线**；**前置部分（封面、学生声明页）的底纹一律不动**（封面表格是学校模板的一部分）；若你确实想用高亮做标记，请在格式化前保留一份原文
- 删除中西文空格：按「中文/日文假名 ⟷ 拉丁字母/数字」判定，**标题编号后、目录条目编号后、图表题注编号后的那一个空格保留**；中英文标点之间的空格、纯英文之间的空格不动
- 封面（「摘要」之前的所有页面）保持原样，不套用正文格式（图片段落行距除外）
- 页眉：**正文及各后置分节自动套用「一级标题（章名）」页眉 —— 新建页眉部件并写入 `STYLEREF "标题 1"` 域，各章自动显示对应章名，无需手动设置**（可在设置中关闭）；前置部分（封面/摘要/目录）原有页眉不动；**域中样式名必须为中文并加引号**（`STYLEREF "标题 1"`），写成英文名或不加引号 Word 会显示「错误！未定义样式」。页眉/页脚距离已按 1.6cm / 2.1cm 设置
- 分节页码按原文档分节划分设置罗马/阿拉伯数字，若原文档节划分特殊，页码格式需在 Word 中微调
